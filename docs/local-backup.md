# 完整本機備份與遷站還原

入口：資料庫管理 → 備份／遷站。與「儲存單張報價 JSON」不同，本備份包含目前網址瀏覽器內的草稿、專案庫、條款範本、分類、單條條款、印章圖片、刪除佇列、OneDrive 目錄與介面／列印設定。

舊站未改版的編輯台可使用只讀輔助頁：https://aaronkino.github.io/qt/assets/migration-backup.html 。請以原本使用舊站的瀏覽器與設定檔開啟，按下下載；不會登入、上傳或清除資料。

## 使用順序

1. 在舊網址下載「完整本機備份」，確認檔案已保存在私人的安全位置。此檔含客戶與印章資料，未加密，不要上傳 GitHub 或公開分享。
2. 到新網址，先下載新網址目前資料的備份作為還原前的安全副本。新站若是空白仍需保留安全副本。
3. 選擇舊站備份檔，檢查來源與項目數量。登入憑證不會帶入備份。
4. 登出 Google／OneDrive，關閉自動儲存並關閉其他 QT 分頁，再勾選已保留備份並確認取代本機資料。
5. 還原後重新載入，逐項檢查草稿、專案、條款與印章；OneDrive 自動儲存預設關閉，需重新登入後自行確認啟用。

## 安全邊界與限制

- 僅讀寫指定的 `kino_quotation_` 白名單；不擷取 sessionStorage、登入 Token、舊同步金鑰或其他網站資料。
- 備份有 SHA-256 完整性檢查碼，但不是來源身分驗證或加密。僅匯入可信來源的備份。
- 匯入先完整驗證，再取代此網址本機資料；不是合併操作，不主動呼叫任何雲端 API。還原前若本機資料又變更，拒絕操作並要求重新備份。
- 寫入失敗會嘗試回復原本內容。瀏覽器儲存空間或裝置故障仍可能導致回復失敗，必須保留下載的安全副本。
- 印章只有雲端版本編號卻沒有本機圖片，或專案引用的印章缺失時，拒絕產生不完整備份。須先讓印章圖片載入到本機。
- 只備份當前瀏覽器設定檔與當前網址；不等於其他手機／瀏覽器也已備份，也不等於 D1／R2 備份。
- 本機備份包含刪除紀錄，但不自動向雲端執行刪除。重新登入同步仍須手動確認差異。

## 驗證

`tests/local-backup.test.mjs` 測試 Token 排除、完整性、缺失圖片、資料型別、還原前變動及空間不足回復。

`tests/mobile-sync-mock.cjs` 用兩個隔離 HTTPS 網址驗證舊站匯出、新站登出狀態匯入、重新載入保留草稿與專案，且沒有增加同步寫入或 OneDrive 上傳。這不是使用者正式資料的備份完成證明。
