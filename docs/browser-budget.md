# 瀏覽器產檔預算（開發分支，未部署）

一般下載PDF、編輯台固定版本圖片驗證、客戶預覽與最終產檔，統一使用 `browser-budget.js`。已簽檔下載、快取待簽PDF與不需重新產檔的重試不啟動瀏覽器。

## 目前保守政策

- 全部QT使用者共用UTC每日480,000毫秒（8分鐘）的應用程式預算。這不是Cloudflare實際計費秒數。
- 每次啟動前，以D1單次條件寫入預留120,000毫秒；剩餘不足則429拒絕，不啟動瀏覽器。
- 同時只允許一個有效產檔租約，啟動間隔至少25秒。跨UTC日也不能跳過舊租約或啟動間隔。
- 啟動後45秒看門狗嘗試關閉瀏覽器，並拒絕此工作後續取用；idle timeout沿用10秒。呼叫端仍保留頁面／PDF既有逾時限制。
- 確認close成功後，以本機經過時間加15秒安全餘裕結算，退回剩餘預留。啟動、關閉或結算結果不確定時不退款；租約最多保留120秒，舊工作不能退掉新租約。
- 額度表缺失或D1異常時503拒絕，不繞過保護。一般報價可改用瀏覽器列印；客戶已接受的簽署保持不可變，額度恢復後只能重試原提交。
- 確定尚未建立的429不會清除管理者已核對的預覽，可等候後重試；不確定的建立回應仍先查清單，避免重複建立。

## 不代表帳號帳單保證

Cloudflare官方目前列出Workers Free瀏覽器每日10分鐘、同帳號共用；Browser Sessions另有每20秒一個新瀏覽器及3個並發的限制。依據：[Pricing](https://developers.cloudflare.com/browser-run/pricing/)、[Limits](https://developers.cloudflare.com/browser-run/limits/)（2026-11-18查閱）。

本保護只涵蓋此Worker的程式入口，不會讀取其他Worker或產品的帳單／用量，也不能精確量測Cloudflare實際計費時間。其他服務使用同帳號額度、平台關閉失敗或用量計算差異，都可能使平台比本預算更早拒絕。正式公開前仍須核對帳號確為Free及當日帳號用量；不得把8分鐘預算宣稱為帳號保證零費用，也不得自行升級Paid或調高上限。

## 部署順序與資料隔離

`0009_browser_budget.sql` 只新增獨立、單列的 `quote_browser_budget` 表，不更新、刪除或重建專案／條款／印章／簽署記錄。尚未套用正式D1。

正式部署前先備份並核對既有migration，再套用這個新增表，最後部署Worker；否則目前已啟用的一般PDF下載會因額度表缺失而拒絕。不得透過清空資料庫重新跑所有migration。回退Worker程式不需要刪除此表。

## 驗證界線

`tests/browser-budget.test.mjs` 使用真正記憶體SQLite，驗證並發原子性、日上限、啟動間隔、跨日、確認關閉後結算、不確定結果保留、看門狗、遲到啟動及過期工作不能退掉新租約。`tests/signing-runtime.cjs` 另於隔離workerd D1套用新表，確認HTTP PDF超額時回429、沒有進入字型／Browser Run流程。

測試沒有呼叫正式Browser Run或修改雲端資料；實際帳號用量及正式看門狗／close行為仍需小量受控驗收。
